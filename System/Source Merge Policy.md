# Source merge policy routing

Source changes in this Itsadoor repository follow [Hogan's canonical policy](https://github.com/itsadoor-llc/itsadoor-engineering/blob/main/docs/SOURCE-MERGE-POLICY.md): complete authorized, reviewed and appropriately validated changes through merge when conflict-free; a conflict requires a concrete yes/no question explaining both merging and not merging in plain language. Draft PRs are an intermediate review state, not a permanent owner-approval queue.

A reusable template follows the actual repository owner's documented merge policy. If the owner has delegated conflict-free source merges, finish them and report the actual merged commit. If no delegation is documented, prepare the concrete PR and ask the owner “Should I merge this — yes or no?” with the changes, material risks, what stays unchanged if no, and the cost of delay. An unanswered question grants no authority. Hogan's permission does not transfer to another person's notebook merely because they copied this starter.

Requests only to explain or review remain read-only. A source merge does not approve every factual claim, complete product acceptance, publish the work, deploy software, or grant private data access. The friend's Review/Keep conversation remains their judgment; saving is distinct from agreement. Conflicts preserve both versions and require the owner choice; do not discard work or repeat repair cycles indefinitely.
